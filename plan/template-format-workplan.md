# 서식관리 — 파일에서 서식 등록 · 본문 서식 적용 작업계획

작성 2026-09-29 · 상태: 계획(미착수)

## 0. 목표와 원칙

- 사용자가 **.hwpx 또는 .odt** 파일을 올리면 **본문에 쓰인 서식**(폰트·크기·굵게·자간·장평·줄간격·문단 간격·단계별 들여쓰기)을 뽑아 서식관리에 등록한다.
- 결재란·등록번호·발신명의·수신자처럼 **문서 틀에 속한 부분은 분석하지 않는다.**
- **가장 중요한 것은 적용이다.** AI 초안을 [본문에 삽입]할 때 등록한 서식대로 들어가야 한다.
- 추출은 규칙 기반으로 한다(AI 불필요). 저장하기 전에 사용자가 확인하고 고칠 수 있어야 한다.
- 원본 파일과 본문 내용은 저장하지 않는다. 서식 값, 파일명, 지문(SHA-256)만 남긴다.

## 1. 실물 분석 결과 (사용자가 올려 준 문서 5건)

### 1-1. 공통으로 확인한 사항

| 항목 | 실측 |
|---|---|
| 온나라 내려받기 형식 | .odt(한컴 변환기 출력). 결재란 표에는 `CellField¡…` 북마크와 `table:protected`가 붙어 있다 |
| 시행문 본문 경계 | 누름틀 `NormalField¡본문¡본문을 입력하십시오` 북마크의 시작~끝이 본문이다 |
| 업무보고 본문 경계 | 본문 누름틀이 없다. 결재란 표 뒤부터 끝까지가 본문이다 |
| 들여쓰기 | **줄 앞 공백 칸 수**와 **내어쓰기**(두 번째 줄 정렬)를 함께 쓴다. 내어쓰기는 기호 뒤나 "라벨 : " 뒤에 맞춘다 |
| 기호 | □는 한컴 사용자 영역 문자(U+F03DA)다. 원문자 중제목(󰊱󰊲)도 사용자 영역 문자다. ○는 `○`·`❍`·`ㅇ`이 섞여 쓰이고, ·는 `·`·`‧`이 섞여 쓰인다 |
| 제목·요약·대제목 | 보고서형은 **표(상자)** 로 만든다: 제목 상자, 요약 상자, `Ⅰ │ 추진 배경` 대제목 막대 |
| 문서마다 규칙이 다름 | □ 폰트만 봐도 HY견고딕 17pt, HY헤드라인M 16pt 등으로 다르다. 그래서 "파일 하나 = 서식 하나"로 등록한다 |

### 1-3. 분석 시 주의할 점

- **한 단계 안에서도 값이 흩어진다.** 예: B의 ㅇ 줄간격이 140~200%로 나뉜다. 단계별로 가장 많이 쓰인 값을 고르고, 확인 화면에서 사용자가 고친다.
- **ODT와 한글은 줄간격 기준이 다르다.** ODT 123%·131%·138%가 한글 160%·170%·180%에 대응하는 것으로 보인다(한글 % ≈ ODT % × 1.3, 가설). 같은 문서를 두 형식으로 저장해 확정한다.
- **단위를 환산한다.** 자간은 ODT의 pt 값을 글자 크기로 나눠 한글 %로 바꾼다(예: -1.20pt ÷ 15pt = -8%). cm는 HWPUNIT로 바꾼다(1cm ≈ 2834.6).
- **HWPX 특이 구조를 처리한다.** 여백 값이 `hp:switch/hp:case` 안에 있는 경우가 있고, 번호가 자동 번호(`hh:heading`)로 붙는 경우가 있다.

## 2. 본문 적용 방식 검토

### 2-1. 현재 동작

- `background.ts`가 기안기 탭의 모든 프레임에 스크립트를 넣고(`world: 'MAIN'`) `HwpCtrl` 객체를 찾는다.
- 누름틀 `본문`으로 이동한 뒤 한 줄씩 `InsertText`와 `BreakPara`(문단 나누기)를 실행한다.
- 결과는 **서식 없는 글자**다. 클립보드 HTML도 맑은 고딕 11pt로 고정되어 있다.
- 기안기는 **한컴 웹기안기**로 판단된다. 근거: ODT 변환기 이름, `NormalField`·`CellField` 누름틀 이름, 기존 `HwpCtrl` 탐지 코드.

### 2-2. 후보 방식 (위에서부터 우선)

| 순위 | 방식 | 반영 범위 | 비고 |
|---|---|---|---|
| ① | `SetTextFile(서식 문서, 'HWPML2X', 'insertfile')` | 전부(글자·문단 서식, 표·상자). 되돌리기 한 번에 취소 | 서식 값으로 HWPML 조각을 만든다. 정확도가 가장 높다 |
| ② | `SetTextFile(html, 'HTML', 'insertfile')` | 폰트·크기·굵게·줄간격·여백·표. 자간·장평은 빠질 수 있음 | 조각을 만들기 쉽다 |
| ③ | 줄마다 `CharShape`·`ParaShape` 실행 후 `InsertText` | 글자·문단 서식. 표는 안 됨 | 기존 반복문에 끼워 넣기만 하면 된다 |
| ④ | 글자만 삽입(현행) + 기호·앞 칸 정리 | 기호, 들여쓰기 칸 | 항상 가능한 최후 수단 |

- **삽입 후 확인:** `GetTextFile('HWPML2X', …)`로 방금 넣은 문단의 서식을 다시 읽어 적용 여부를 판정한다. 결과를 "서식 적용 완료 / 일부 적용 / 글자만 삽입"으로 알린다.
- **누름틀 주의:** 누름틀 `본문`에는 자체 글자 서식이 있다. 삽입한 글자가 그 서식을 물려받지 않도록 서식을 명시적으로 지정해야 한다.
- **덤 기능(선택):** 같은 `GetTextFile`로 **지금 열린 기안기 문서에서 서식을 바로 가져오는** 기능도 만들 수 있다. 파일을 올리지 않아도 된다.

### 2-3. 결정 방식

①~③ 중 무엇이 동작하는지는 **실제 온나라 기안기에서만** 확인할 수 있다. 그래서 P0 진단으로 사용 가능한 방식을 확정하고, 적용 엔진은 **가능한 방식 중 가장 좋은 것부터 시도하고, 안 되면 다음 방식으로 내려가도록** 만든다.

## 3. 데이터 구조

`DraftTemplate`에 선택 필드 `format`을 추가한다. 기존 서식과 호환된다.

```ts
interface TemplateFormat {
  version: 1;
  source: { fileName: string; kind: 'hwpx' | 'odt'; sha256: string; importedAt: number };
  docKind: 'official' | 'report';          // 시행문 본문형 | 보고서·업무보고형
  page?: { widthMm: number; heightMm: number; marginMm: { top: number; bottom: number; left: number; right: number } };
  levels: LevelStyle[];                    // 위 단계부터 순서대로
  boxes?: { title?: BoxStyle; summary?: BoxStyle; chapter?: BoxStyle };
}
interface LevelStyle {
  key: 'num1' | 'ga' | 'section' | 'item' | 'sub' | 'detail' | 'circled' | 'note' | string;
  glyph: string;          // 원본에 쓰인 기호 그대로(❍, ㅇ, U+F03DA …)
  sample: string;         // 확인 화면용 예시 1줄(최대 30자)
  leadSpaces: number;     // 앞 공백 칸 수
  char: { font: string; sizePt: number; bold: boolean; spacingPct: number; ratioPct: number };
  para: { lineSpacingPct: number; beforePt: number; afterPt: number; hangingPt: number; align: 'left' | 'justify' | 'center' };
  hangingMode: 'none' | 'marker' | 'label';
  count: number;          // 근거 문단 수(신뢰도 표시용)
}
```

- 단위는 적용 대상인 한글 기준(pt, %, HWPUNIT)으로 저장한다. ODT 값은 가져올 때 환산한다.
- 대제목(□·Ⅰ) 글자는 기존 `sections`(필수 주요 항목)에 미리 채워 두고, 사용자가 고친다.

**테스트와 자료 원칙**
- **사용자가 직접 올려 준 문서만 쓴다.** 다른 폴더는 탐색하지 않고, 자료가 더 필요하면 사용자에게 요청한다.
- 저장소에는 실물 구조를 본뜬 **합성 테스트 파일**(fflate로 만든 최소 XML)만 넣는다. 실물 문서는 저장소에 넣지 않는다.

## 5. 위험 요소

- **웹기안기 API가 설치형 한글 API와 다를 수 있다.** 비동기 콜백 방식이거나 일부 명령을 지원하지 않을 수 있다. P0에서 확정한다.
- **폰트가 없을 수 있다.** 휴먼명조·HY헤드라인M이 웹기안기 글꼴 목록에 없으면 대체 폰트로 표시된다. 진단 때 글꼴 목록도 함께 확인한다.
- **사용자 영역 문자:** 한컴 전용 기호(□, 원문자)는 드로어 미리보기에서 깨질 수 있다. 미리보기에서만 일반 문자로 바꿔 보여 준다.
- **"라벨 : " 정렬 내어쓰기**는 글자 폭 계산이 필요하다. 1차는 단계별 고정값, 2차에 정밀화한다.
- **줄간격 환산식(×1.3)은 가설이다.** P1에서 확정한다.
