# 온나라 sAIde (onNara.sAIde)

> **공문 열람의 패러다임을 바꿉니다 — 문서를 일일이 열어보지 않고 목록에서 바로 파악하고 처리하는 온나라 전용 Edge AI 사이드패널**  
> 끝없는 새 창 띄우기와 첨부 다운로드의 반복에서 벗어나, 가장 스마트하고 안전한 업무 어시스턴트를 경험하세요.

## 시스템 소개: 행정업무 생산성을 극대화하는 온나라 전용 AI 파트너

**온나라 sAIde**는 공무원 및 공공기관 실무자가 온나라 2.0 전자문서 시스템을 사용할 때 겪는 반복적인 비효율을 해소하기 위해 탄생한 Microsoft Edge 전용 AI 사이드패널 확장 프로그램(Manifest V3)입니다.

단순한 대화형 챗봇이 아닙니다. 온나라 전자문서 화면과 유기적으로 결합하여 실무자의 가장 많은 시간을 앗아가는 **'공문 열람·분석'**, **'첨부파일 취합'**, **'오늘 볼 문서 고르기'** 업무를 획기적으로 혁신합니다.

사이드패널은 **공유/공람 · AI · 일정 · 도구** 네 개의 탭으로 구성됩니다.

### 🌟 핵심 혁신 가치 1: 문서등록대장에서 문서를 일일이 열어보지 않고도 AI 요약·분석 완료!
> **"수십 건의 공문을 하나하나 클릭해서 창 열고 뷰어 로딩을 기다리던 시대는 끝났습니다."**

* **목록 체크만으로 백그라운드 자동 분석**: 문서등록대장이나 접수대기함에서 관심 있는 공문들을 체크박스로 선택하기만 하면, sAIde가 원본 화면을 그대로 유지한 채 백그라운드에서 각 문서의 본문을 스스로 회수해 분석합니다.
* **핵심·조치사항 원스톱 도출 (Action Card)**: 단순한 줄글 요약에 그치지 않고, 우리 과가 처리해야 할 **세부 할 일(To-Do)**, **제출 서식 및 제출물**, **제출 마감 기한**, **소관 부서 및 문의처**를 정형화된 카드로 일목요연하게 도출합니다.
* **원문 실시간 대조 검증 (No Hallucination)**: AI가 추출한 기한 날짜와 근거 문장을 시스템 코드가 원문 텍스트와 즉시 대조하여 `원문 확인` 배지를 부여하므로, 안심하고 업무에 바로 활용할 수 있습니다.
* **다중 공문 비교·분석 (`/비교`)**: 여러 관련 공문을 한 번에 선택해 지침 변경 사항, 공통점, 상충 내용까지 한 화면에서 즉시 비교·대조합니다.

### 🚀 핵심 혁신 가치 2: 문서등록대장에 등록된 문서의 본문(HTML·PDF) 및 첨부파일 일괄 자동 다운로드!
> **"본문과 첨부파일 하나 받으려고 매번 상세 화면에 들어가 다운로드 링크를 일일이 누르고 계셨나요?"**

* **원클릭 일괄 다운로드**: 문서등록대장에서 여러 문서를 선택한 뒤 `다운로드` 버튼(또는 `@첨부` 명령) 한 번만 누르면, 선택한 공문의 본문(HTML/PDF)과 모든 첨부파일(HWP, HWPX, PDF 등)을 백그라운드에서 한 번에 묶어 내려받습니다.
* **다운로드 대상 선택 모드**: 업무 필요에 따라 **첨부파일만**, **공문 본문만(HTML 또는 PDF)**, 혹은 **본문 + 첨부파일 전체**를 골라 저장할 수 있습니다.
* **안정적인 브라우저 순차 처리**: 브라우저의 다운로드 세션을 정밀하게 감시하여, 한 파일의 전송 완료를 확인한 후 다음 파일로 안전하게 넘어가는 스마트 대기열을 탑재했습니다. 누락이나 다운로드 충돌이 전혀 없습니다.
* **AI 모델 없이도 초고속 구동**: 순수 브라우저 자동화 기술로 동작하므로 로컬 AI 모델이 꺼져 있거나 오프라인 상태에서도 100% 즉시 동작합니다.
* **작업 이력 보존 및 원클릭 열기**: 패널을 닫았다가 다시 열어도 이전 다운로드 이력이 유지되며, `파일 열기` 및 `폴더 열기` 버튼을 지원하여 파일 탐색기를 찾아 헤맬 필요가 없습니다.

### 📅 핵심 혁신 가치 3: 공문에서 도출된 내 할 일과 기한을 그대로 일정으로!
> **"공문을 읽고 나서 수첩에 기한을 옮겨 적고, 그 수첩을 다시 확인하는 일을 없앱니다."**

* **말로 일정 관리**: `@일정 내일까지 예산안 제출`, `@일정 이번 주 일정 보여줘`처럼 문장으로 등록·조회·수정·삭제합니다. 등록·수정·삭제는 반드시 확인 카드를 거치며, **모델이 만드는 것은 후보일 뿐 저장은 사용자가 누를 때만** 일어납니다.
* **분석 결과에서 곧바로 등록**: `/조치` 분석 답변 아래의 **`일정으로 등록`** 버튼을 누르면 우리 과가 해야 할 일과 제출 기한이 후보로 뜨고, **체크한 항목만** 일정 탭으로 들어갑니다. AI가 뽑았다고 해서 자동으로 등록되는 경로는 없습니다.
* **공문식 날짜 자동 해석**: `2026. 9. 30.(수)`, `9월 30일 18:00까지` 같은 공문 표기를 달력 날짜로 바꿔 D-day로 관리합니다. 연도가 생략된 기한은 그 공문의 **보고일자를 기준으로** 해석하고 `연도 추정` 배지를 남겨 사용자가 확인할 수 있게 합니다.
* **월간 달력과 D-day 목록을 함께**: 월·주·일 달력으로 이번 달에 무엇이 몰려 있는지 한눈에 보고, 목록 보기로는 지금 급한 것부터 처리합니다.
* **지난 기한을 숨기지 않음**: 달력에서는 붉은 칩과 점으로, 목록에서는 기한 지남 · 오늘 · 이번 주 · 나중 · 기한 미정 구간의 맨 위에 `D+n`으로 남습니다.
* **패널을 닫아도 울리는 알림**: 브라우저가 실행 중이면 사이드패널을 닫아 두어도 하루 한 번(기본 오전 9시) 지난 기한·오늘·내일 기한을 묶어 알립니다.
* **근거를 잃지 않는 내보내기**: 근거 문장까지 담은 **CSV**(기록용)와 남은 기한만 담은 **ICS**(달력용)로 내보낼 수 있습니다.

### 🗂️ 핵심 혁신 가치 4: 아침에 받은문서를 대신 훑어, 오늘 볼 것만 골라 둡니다!
> **"받은문서 40건을 위에서부터 훑어 내리며 '이건 내 일인가'를 판단하는 시간을 없앱니다."**

* **문서를 열지 않고 목록만 읽습니다**: 온나라 `공유/공람 > 받은문서`의 목록 표(제목·보고일자·수발신자·부서·붙임·열람)만 읽습니다. 본문을 열지 않으므로 **문서는 `미열람` 그대로 남습니다.** 열람 처리는 온나라 서버가 상세 화면을 내려줄 때 기록하므로 확장이 되돌릴 수 없고, 그래서 *열지 않는 것*이 유일한 방법입니다.
* **세 갈래 분류**: `기한 임박`(코드가 제목에서 날짜를 읽어낸 것) · `내 업무로 보임` · `단순 공람`으로 나누고, **왜 그 갈래인지 이유를 문장으로 함께 보입니다.**
* **모델이 꺼져 있어도 나옵니다**: 분류는 코드 규칙만으로 완결됩니다. Ollama가 켜져 있으면 목록 전체에 대해 **1회 호출**로 `내 업무`·`단순 공람`만 보강하며, 실패해도 규칙 결과가 그대로 남습니다. 기한 갈래는 모델이 뒤집지 못합니다.
* **패널을 닫아 두어도 동작합니다**: `chrome.alarms`가 서비스 워커를 깨워 하루 한 번(기본 오전 9시 이후 첫 사용 시) 확인합니다. 브라우저만 실행 중이면 됩니다. **기본값은 꺼짐** — 켜는 순간이 사용자의 승인입니다.
* **일정으로 바로 잇기**: 카드의 `일정 등록`을 누르면 제목·기한·근거가 그대로 일정 탭 항목이 됩니다.

## 핵심 보안 및 신뢰성 원칙

* 🔒 **100% 로컬 추론 우선 (Local-First)**: 사용자 PC에 설치된 경량 LLM(Ollama `gemma4:e2b`, `bge-m3`)을 기본 엔진으로 사용하여 민감한 공문 본문과 개인정보가 외부 클라우드로 단 1바이트도 유출되지 않습니다.
* 🛡️ **사람 중심 안전 승인 (Fail-Closed & Approval)**: 브라우저 조작이나 화면 이동이 필요할 때는 반드시 사용자에게 사전 승인 카드(`ApprovalCard`)를 제시하며, 사람의 명시적 승인 없이 무단으로 온나라 시스템을 조작하지 않습니다.
* 📄 **행정 표준 뷰어 완벽 지원**: HTML 텍스트뿐만 아니라 브라우저 내장 PDF 뷰어로 열리는 공문도 오프스크린 파서(한국어 CMap 동봉)를 통해 텍스트 레이어를 완벽히 추출합니다.
* ⚡ **문맥 경계 자동 분리 (Context Isolation)**: 새 문서를 열거나 명령을 실행하면 모델 전송 문맥(`contextFrom`)이 자동 격리되어 이전 공문 내용이 섞이거나 토큰이 낭비되지 않습니다.

## 설치 및 빠른 시작 가이드

온나라 sAIde를 개발 환경 또는 업무 PC에서 구동하는 단계별 안내입니다.

### 1. 사전 요구사항

1. **Microsoft Edge** 브라우저 (Chromium 기반)
2. **Node.js** 24.x 이상 및 **npm** 11.x 이상
3. **Ollama** (0.34.1 이상 권장)
   * 공식 웹사이트([ollama.ai](https://ollama.ai))에서 다운로드 및 설치

### 2. Ollama 모델 다운로드 및 실행

터미널(PowerShell 또는 명령 프롬프트)에서 기본 대화 모델과 임베딩 모델을 내려받습니다.

```powershell
# 1. 기본 대화 모델 설치 (Gemma 4 e2b 권장)
ollama pull gemma4:e2b

# 2. 기본 임베딩 모델 설치 (BGE-M3 권장)
ollama pull bge-m3:latest

# 3. 모델 정상 설치 확인
ollama list
```

> **CORS(Cross-Origin) 허용 설정 안내:**  
> 브라우저 확장에서 로컬 Ollama에 접근하려면 Ollama 환경 변수에 확장의 Origin을 허용해야 합니다.  
> Windows 환경 변수에서 `OLLAMA_ORIGINS`를 `chrome-extension://*`로 설정한 후 Ollama 서비스를 재시작해 주세요.

### 3. 저장소 복제 및 의존성 설치

```powershell
# 1. 의존성 설치
npm ci

# 2. 로컬 환경 변수 파일 생성
Copy-Item .env.example .env.local

# 3. 정적 타입 검사 및 테스트 실행
npm run compile
npm test
```

### 4. 프로덕션 빌드 및 Edge 브라우저에 확장 로드

```powershell
# 1. Edge MV3용 번들 빌드
npm run build

# 2. 빌드 무결성 및 색상 대비 검증
npm run verify
```

빌드가 완료되면 프로젝트 루트의 `.output/edge-mv3` 디렉터리에 배포 가능한 확장 패키지가 생성됩니다.

#### Microsoft Edge 브라우저에 등록하는 절차:
1. Microsoft Edge 브라우저를 열고 주소창에 `edge://extensions`를 입력합니다.
2. 좌측 하단(또는 상단)의 **개발자 모드(Developer mode)** 토글 스위치를 켭니다.
3. 상단에 나타난 **압축 해제된 확장 로드(Load unpacked)** 버튼을 클릭합니다.
4. 파일 선택 대화상자에서 프로젝트 디렉터리 내의 `.output/edge-mv3` 폴더를 선택합니다.
5. 설치가 완료되면 Edge 브라우저 우측 상단 도구 모음에 **온나라 sAIde** 아이콘이 표시됩니다.
6. 아이콘을 툴바에 고정(고정 핀 아이콘 클릭)한 뒤 클릭하여 **오른쪽 사이드패널**을 엽니다.

## 사용자 매뉴얼 (화면별 상세 안내)

### AI 사이드패널 및 대화 인터페이스

![온나라 sAIde AI 대화 및 문서 요약 화면](docs/screenshots/01-chat.png)
*(사용 설명용 예시 · 온나라 sAIde 실제 UI / 샘플 데이터)*

사이드패널은 상단의 4대 탭(**공유/공람**, **AI**, **일정**, **도구**)으로 구성되며, 업무 시작 시 수신된 공문 브리핑을 확인하고, **AI** 탭에서 공문 요약, 질의응답, 비교 분석을 신속하게 수행할 수 있는 업무 동선을 제공합니다.

* **상단 헤더(Header) 및 탭 구성**:
  * 처리 위치와 모델명이 담긴 칩(`내 PC · gemma4:e2b`)이 표시되며, 누르면 설정 화면이 열립니다.
  * 현재 버전은 로컬 Ollama로만 추론하므로 칩은 언제나 `내 PC`를 가리킵니다(범정부 AI 공통기반 연동은 계획 단계).
  * 상단 탭 전환 막대에서 **공유/공람**(아직 처리하지 않은 문서 수 배지), **AI**, **일정**(기한 임박 배지), **도구** 탭을 클릭하여 즉시 전환할 수 있습니다.
  * 우측 상단의 **현재 대화 초기화(Trash)** 아이콘을 누르면 진행 중인 작업을 안전하게 취소하고 현재 세션의 대화와 첨부 문맥을 깨끗이 비웁니다(다른 세션은 보존).
* **문서 본문 첨부 칩 (`PageContextChip`)**:
  * 온나라 목록이나 문서 본문에서 읽어 들인 문서의 제목, 글자 수, 파싱 방식이 칩 형태로 표시됩니다.
  * 칩 우측의 `×` 버튼을 누르면 해당 문서 본문과 관련 문답이 문맥에서 즉시 제외되어 새 작업을 시작할 수 있습니다.
* **대화 목록 (`MessageList`) 및 일정 등록 연동**:
  * AI가 작성한 모든 답변에는 **`AI 생성 · 검토 필요`** 배지가 붙어 사용자의 최종 검토를 유도합니다.
  * 공문 요약이나 핵심·조치사항 답변 바로 아래에 **`📅 일정으로 등록 (n건)`** 카드가 자동 노출되어, 도출된 업무 기한과 To-Do를 검토 후 클릭 한 번으로 일정 탭에 등록할 수 있습니다.
  * 각 메시지 하단의 **복사** 아이콘으로 내용을 클립보드에 복사하거나, **삭제** 아이콘으로 특정 메시지만 대화 기록에서 제거할 수 있습니다.

### 명령 체계 — `/`와 `@`

입력창에 `/` 또는 `@`를 치면 명령 목록이 뜹니다. **접두 문자가 결과를 어디서 볼지 알려 줍니다.**

| 접두 문자 | 뜻 | 명령 |
|:---:|:---|:---|
| **`/`** | 결과가 **AI 창 안에서 끝나는** 명령입니다. | `/요약` `/조치` `/비교` `/읽기` `/새로고침` `/기억` |
| **`@`** | **다른 탭에 남는 것을 다루는** 명령입니다. 일정 항목, 다운로드 작업, 브리핑 결과처럼 대화가 끝나도 남는 것들입니다. | `@일정` (일정 탭) · `@첨부` (도구 탭) · `@브리핑` (공유/공람 탭) |

> 💡 **화면은 옮겨지지 않습니다.** `@` 명령을 실행해도 AI 창에 그대로 머무릅니다. 결과에 **`일정 탭에서 보기`** 같은 링크가 함께 오고, 그 링크를 눌러야 해당 탭으로 넘어갑니다 — 그것도 **그 항목이 강조된 상태로** 열립니다. 지시한 자리에서 답을 읽고 이어서 다음 지시를 내릴 수 있게 하려는 것입니다.

> 💡 예전 이름인 `/첨부`를 쳐도 자동완성이 `@첨부`를 보여 주고, 그대로 Enter를 눌러도 실행됩니다.

#### `/` — 온나라 목록 연동 명령

온나라 받은문서나 문서등록대장 목록에서 원하는 문서들을 체크박스로 선택한 후 명령을 입력하면 AI가 정형화된 작업을 즉시 수행합니다.

| 명령어 | 영문 별칭 | 주요 동작 및 활용법 | AI 모델 사용 |
|:---|:---|:---|:---:|
| **/요약** | `/summary` | 체크한 문서를 순차적으로 열어 핵심 내용을 요약합니다. 뒤에 추가 지시를 붙일 수 있습니다.<br>*(예: `/요약 예산 및 추진 일정 위주로`)* | ✅ |
| **/조치** | `/actions` | 핵심·조치사항 카드(요약, 할 일, 제출물, 기한, 문의처)를 생성하고 원문과 대조합니다. | ✅ |
| **/비교** | `/compare` | 체크한 여러 공문을 한 번에 읽어 공통점, 차이점, 연관성을 비교 분석합니다.<br>*(예: `/비교 변경된 지침 내용을 대조해줘`)* | ✅ |
| **/읽기** | `/read` | 요약 과정 없이 공문 본문 텍스트만 읽어 대화 문맥에 즉시 첨부합니다. 이후 자유롭게 후속 질문이 가능합니다. | ❌ |
| **/새로고침** | `/refresh` | 온나라 목록의 최신 상태 및 체크박스 선택 현황을 다시 읽어와 패널에 알려줍니다. | ❌ |
| **/기억** | `/recall`, `/memory` | 저장된 기억(과거에 읽은 문서)에서 찾아 대화에 붙입니다. 뜻이 가까운 글(벡터)과 **정확히 그 글자**(키워드)를 함께 찾습니다 — `2026-1234호` 같은 표기도 걸립니다. 설정에서 **기억을 켠 경우에만** 동작합니다.<br>*(예: `/기억 예산 편성 지침`)* | 임베딩만 |

#### `@` — 다른 탭이 주화면인 명령

| 명령어 | 영문 별칭 | 주요 동작 및 활용법 | AI 모델 사용 |
|:---|:---|:---|:---:|
| **@일정** | `@schedule` | 자연어로 일정을 등록·조회·수정·삭제합니다. 답변의 항목 제목이 곧 **일정 탭의 그 항목으로 가는 링크**입니다.<br>*(예: `@일정 내일까지 예산안 제출`)* | ✅ |
| **@첨부** | `@attach` | 체크한 문서의 첨부파일을 브라우저를 통해 백그라운드에서 모두 순차 다운로드합니다. (대용량 링크 첨부 `.html` 자동 처리 지원) 결과에 **`도구 탭에서 보기`** 링크가 붙어, 누르면 그 작업이 강조된 채로 열립니다. | ❌ |
| **@브리핑** | `@brief`, `@inbox`, `@공람` | 지정해 둔 `공유/공람 > 받은문서` 목록을 지금 한 번 읽어 갈래로 나눕니다. 온나라 목록 화면을 보고 있지 않아도 동작합니다(저장해 둔 대상 위치를 씁니다). | 보강 1회 |

> 💡 **명령어 뒤에 "전체"를 붙이는 경우:**  
> `/요약 전체`, `@첨부 전체`와 같이 뒤에 `전체`를 붙이면 현재 화면에 렌더링된 모든 문서를 대상으로 실행합니다.

#### 일반 대화(명령 없는 문장)와의 차이점
* **명령 없는 문장**: 화면을 다시 읽지 않고 이미 대화에 붙어 있는 본문과 앞선 답변만을 바탕으로 질의응답합니다. *(예: "기한이 가장 빠른 것부터 표로 정리해줘", "위 내용에서 주의할 점은?")*
* **새 문서 작업 시**: 새 문서를 다룰 때는 `/요약` 등의 목록 명령을 실행하면 자동으로 이전 대화와 분리된 새 문맥(`contextFrom`)이 시작되어 내용이 섞이지 않습니다.

### `@일정` — 말로 하는 일정 관리

일정 탭을 열어 폼을 채우는 대신, AI 탭에서 문장 하나로 일정을 다룹니다.

| 하고 싶은 일 | 이렇게 말합니다 |
|:---|:---|
| 등록 | `@일정 내일까지 예산안 제출` · `@일정 9월 30일 18시까지 실적보고서 제출` |
| 조회 | `@일정 이번 주 일정 보여줘` · `@일정 5월 전체 일정` · `@일정 예산 관련 뭐 남았지` |
| 수정 | `@일정 실적보고서 기한 10월 2일로 미뤄줘` · `@일정 예산안 제출 완료했어` |
| 삭제 | `@일정 교육 신청 지워줘` |

**결과를 보는 방법**

조회하면 목록이 **AI 창에** 그대로 나옵니다. 각 항목의 제목이 링크이고, 누르면 일정 탭이 그 항목의 날짜로 열리며 해당 줄이 잠시 강조됩니다. 목록 아래의 `일정 탭에서 보기`를 누르면 **물어본 범위 그대로**(하루면 일 보기, 한 주면 주 보기, 한 달이면 월 보기) 열립니다. 등록·수정한 항목도 같은 방식으로 바로 확인할 수 있습니다.

**이 기능이 지키는 네 가지 원칙**

1. **모델은 분류만 합니다.** 무엇을 하려는지(등록/조회/수정/삭제)와 어떤 값인지만 모델이 읽고, 화면에 보이는 **목록과 답변 문장은 코드가 저장소에서 직접 읽어 만듭니다.** 대화 모델에게는 저장된 일정이 보이지 않으므로, 목록을 모델에게 맡기면 없는 일정을 지어냅니다.
2. **누르기 전에는 아무것도 저장되지 않습니다.** 등록·수정·삭제는 예외 없이 입력창 위의 **확인 카드**를 거칩니다. 카드에는 무엇이 어떻게 바뀌는지가 항목마다 표시됩니다.
3. **대상을 짐작하지 않습니다.** "실적보고서 미뤄줘"가 두 건에 걸리면 하나를 골라 주지 않고 둘 다 내놓습니다. 딱 하나가 걸렸을 때만 미리 체크되며, **범위 삭제는 "전부 지워"라고 말했더라도 미리 체크하지 않습니다**(되돌릴 수 없기 때문입니다).
4. **날짜는 코드가 검산합니다.** "5월 전체 일정"을 모델이 이번 주로 줄여 놓아도, 코드가 문장에서 뽑은 범위로 바로잡습니다. 오늘·내일·이번 주·다음 달·`N월 N일`·`6월부터 12월까지`·`2026년도` 모두 코드가 직접 읽습니다.

> ⚠️ 등록한 일정은 **업무 항목**입니다. 시작·종료 시각이 있는 약속이 아니라 기한 하나와 완료 여부를 갖습니다. 장소·반복·참석자는 다루지 않습니다.

### 처음 열었을 때 — 3장짜리 사용 안내

사이드패널을 처음 열면 세 장짜리 안내가 뜹니다. ① 목록에서 체크하고 명령하기 ② `/`와 `@`의 차이 ③ 공문의 기한을 일정 탭으로 보내기 — 이 셋만 담았습니다.

어느 장에서든 `건너뛰기`나 `Esc`로 닫을 수 있고, 다시 보려면 **설정 → 정확도 기록 → `사용법 다시 보기`**를 누른 뒤 패널을 다시 여세요.

### 같은 공문을 다시 분석할 때 (분석 결과 캐시)

`/요약`·`/조치`는 문서 한 건에 수십 초가 듭니다. 온나라 업무는 목록과 문서를 오가는 일이 잦아 같은 공문을 다시 분석하는 일이 흔한데, 그때마다 같은 값을 다시 치를 이유가 없습니다.

* **본문은 언제나 다시 읽습니다.** 제목만 같고 내용이 바뀐 공문(정정·재통보)에 지난 요약을 보여 주지 않기 위해서입니다. 아끼는 것은 비싼 쪽(AI 모델)입니다.
* 본문이 **한 글자도 달라지지 않았을 때만** 저장해 둔 분석을 그대로 보여 주고, 답변에 `(날짜) 분석 결과 재사용` 배지를 붙입니다. 숨기지 않습니다.
* 지시 문장(`/요약 예산 위주로`)이나 모델을 바꾸면 다른 결과이므로 새로 분석합니다.
* 재사용된 답변이 있으면 입력창 위에 `다시 분석` 버튼이 나타납니다. 누르면 캐시를 쓰지 않고 같은 명령을 처음부터 돌립니다.
* 저장 건수 확인과 비우기는 설정 → `정확도 기록`에 있습니다.

### 맞았는지 알려 주기 (정확도 피드백)

AI 답변 아래와 기한 후보 옆에 `맞음`·`틀림` 버튼이 있습니다. 한 번 누르면 기록되고, 같은 버튼을 다시 누르면 취소됩니다. 사유는 묻지 않습니다.

* **왜 두었나**: `원문 확인` 배지는 그 한 건의 판단을 돕지만, "이 도구가 지금까지 얼마나 맞았는가"는 아무도 알 수 없었습니다. 모델을 바꿔도 되는지, 기관에 도입 근거로 낼 수 있는지를 판단할 수치가 여기서 나옵니다.
* **어디에 쌓이나**: 설정 → `정확도 기록`에 누적 정확도와 핵심·조치사항 / 기한 후보 / 문서 요약별 표로 보입니다.
* **밖으로 나가지 않습니다**: 이 브라우저의 로컬 저장소에만 남습니다. 공문 제목조차 기록하지 않습니다.

### 핵심·조치사항 카드 (Action Card)

`/조치` 명령을 실행하면 단순 줄글 요약이 아니라 실무자가 즉시 후속 업무에 반영할 수 있는 구조화 카드가 생성됩니다.

* **요지 (Summary)**: 공문의 핵심 취지와 목적 요약
* **할 일 (To-Do)**: 담당 부서/담당자가 이행해야 할 세부 업무 목록
* **제출물 (Deliverables)**: 회신해야 할 공문, 서식, 첨부 보고서 등
* **기한 (Deadline)**: 제출 마감일 및 처리 시한
* **근거 문장 (Source Anchor)**: 도출된 내용이 실제 원문의 어느 문장에서 발췌되었는지 명시

> **원문 대조 및 기한 보정 알고리즘:**  
> 모델이 추출한 기한과 근거 문장을 시스템 코드가 원문과 실시간 대조합니다. 원문에 일치하는 문장이 있으면 **`원문 확인`**, 일치하지 않으면 **`원문에서 찾지 못함`** 배지를 부착합니다. 또한 모델이 놓친 "~까지", "~일한" 등의 기한 표현은 코드가 원문에서 직접 정규식으로 찾아내어 보완합니다.

### 에이전트 안전 실행 및 승인 시스템

![온나라 sAIde 브라우저 작업 승인 카드](docs/screenshots/02-approval.png)

온나라 sAIde는 사용자가 지시하지 않은 위험한 브라우저 동작을 무단으로 실행하지 않는 **Fail-Closed 안전 모델**을 준수합니다.

### 공유/공람 탭 (자동 브리핑)

![온나라 sAIde 공유/공람 브리핑 화면](docs/screenshots/08-inbox.png)
*(사용 설명용 예시 · 온나라 sAIde 실제 UI / 샘플 데이터)*

사이드패널 첫 번째 탭인 **공유/공람**은 온나라 `공유/공람 > 받은문서` 목록을 대신 훑어, 오늘 볼 문서를 갈래로 나눠 두는 자리입니다. 탭 이름 옆 배지는 **아직 처리하지 않은 문서 수**입니다.

> ℹ️ 화면이 보여 주는 것은 "이번에 새로 들어온 것"이 아니라 **아직 처리하지 않은 것**입니다. 아침 알림을 놓친 날에도 화면이 비어 있지 않습니다.

**1) 대상 화면 지정 (처음 한 번)**

온나라에서 `공유/공람 > 받은문서` 목록을 연 뒤, 이 탭의 **`이 화면을 브리핑 대상으로 지정`**을 누릅니다. 목록의 URL·프레임 경로·조회 폼 조건까지 함께 저장되므로, **이후에는 그 목록을 열어 두지 않아도** 로그인된 온나라 탭에서 저장한 목록 조회 요청을 백그라운드로 전송합니다(보고 있던 화면은 그대로 둡니다). 첫 페이지부터 마지막 페이지까지 모두 읽으며, 지정할 때의 검색 조건과 브리핑의 포함·제외 키워드를 적용합니다. 지정한 화면은 설정 → `공유/공람 브리핑` → `대상 화면`에서 확인하고 해제할 수 있습니다.

**2) 확인하는 방법**

* **자동(하루 한 번, 기본값)**: 설정에서 `자동 브리핑`을 켜면 정한 시각(기본 오전 9시) 이후 브라우저를 처음 쓸 때 하루 한 번 확인합니다. **사이드패널은 닫혀 있어도 되지만 브라우저는 실행 중이어야 하며, 온나라에 로그인돼 있어야 합니다.** 패널이 열려 있으면 패널이 실행하고, 닫혀 있으면 서비스 워커가 규칙 분류만으로 브리핑한 뒤 알림을 띄웁니다.
* **자동(주기 확인)**: `확인 주기`를 30분·1시간·2시간·4시간 중에서 고르면, 업무시간(기본 9~18시, 주말 제외) 안에서 그 간격마다 확인합니다. **이미 브리핑한 문서는 다시 알리지 않으므로, 주기를 짧게 잡아도 새 문서가 들어왔을 때만 알림이 뜹니다.** 확인할 때 공유/공람 화면을 열거나 탭을 전환할 필요가 없습니다. 온나라 세션이 끊겨 실패가 이어지면 간격을 스스로 늘려(3회 연속 2배, 6회 연속 4배) 같은 실패를 되풀이하지 않습니다.
* **수시**: 이 탭의 **`지금 확인`** 버튼, 또는 AI 탭에서 **`@브리핑`**.

**3) 읽어 주는 내용**

머리말에 `확인 시각 · 목록 n건 · 새 문서 n건`이 표시되고, 그 아래로 카드가 갈래별로 쌓입니다.

| 갈래 | 뜻 | 판단 주체 |
|:---|:---|:---|
| **기한 임박** | 제목에서 날짜를 읽어낸 문서 | 코드 (모델이 뒤집지 못함) |
| **내 업무로 보임** | 관심 키워드가 걸리거나 조치를 요구하는 말이 있는 문서 | 코드 규칙 + 모델 보강 1회 |
| **단순 공람** | 나머지 | 코드 규칙 + 모델 보강 1회 |
| **범위 밖** | 설정한 대상 범위에 들지 않은 문서. **버리지 않고 접어 둡니다** | 코드 (키워드) |

각 카드에는 **왜 그 갈래로 보았는지 이유**가 함께 적힙니다. 카드에서 `일정 등록`(또는 `할 일 작성`)을 누르면 제목·기한·근거를 바탕으로 세부 조치 사항을 다듬어 곧바로 일정 탭 항목으로 등록할 수 있고, `넘기기`를 누르면 다음 브리핑에 다시 올라오지 않습니다. `맞음`·`틀림`으로 분류가 맞았는지 알려 줄 수 있으며, 그 수치는 설정의 정확도 표에 `공유/공람 분류`로 집계됩니다.

**4) 열람 상태를 지키는 방법**

![온나라 sAIde 공유/공람 브리핑 설정 화면](docs/screenshots/09-briefing-settings.png)
*(사용 설명용 예시 · 온나라 sAIde 실제 UI / 샘플 데이터)*

* 기본값은 **`목록만 읽기 (미열람 유지)`**입니다. 목록 표만 읽고 본문을 열지 않으므로 문서는 `미열람` 그대로 남습니다.
* 브리핑 전후로 **열람 상태가 바뀐 문서가 있으면 그 건수를 머리말에 알립니다.** 모델의 주장이 아니라 코드가 목록의 열람 칸을 대조해 센 값입니다.
* `브리핑한 문서를 열어 열람 처리`를 고르면 상한(기본 5건)까지 문서를 엽니다. **되돌릴 수 없으므로** 설정 화면에 경고를 함께 띄우며, 이 동작은 받은문서 목록을 보고 있는 탭에서 확인할 때만 실행됩니다.
* **대상 범위**는 `전체` 또는 `키워드(포함·제외)`로 정합니다. 띄어쓰기와 괄호 표기는 무시하고 대조하며, 범위 밖 문서도 버리지 않고 접어 둡니다(키워드를 넓히면 되살아납니다).
* 원장 보관 기간은 기본 60일입니다. 같은 문서를 두 번 브리핑하지 않도록 보고일자·수발신자·제목으로 문서를 식별하며, **읽지 못하고 건너뛴 실행과 그 사유도 기록에 남깁니다**(빈 브리핑을 "오늘은 문서가 없구나"로 오해하지 않도록).

### 일정 탭 (기한·후속조치 보드)

![온나라 sAIde 일정 탭 (기한·후속조치 보드) 화면](docs/screenshots/07-schedule.png)
*(사용 설명용 예시 · 온나라 sAIde 실제 UI / 샘플 데이터)*

사이드패널 상단의 **일정** 탭은 공문에서 도출된 "내가 할 일"과 그 기한을 관리하는 개인 업무 보드입니다. 약속 시각을 적는 달력이 아니라 **처리 기한과 완료 여부**를 다룹니다.

* **말로 등록·조회하기**: AI 탭에서 `@일정 내일까지 예산안 제출`처럼 치면 확인 카드를 거쳐 여기에 쌓입니다. AI 창의 답변에 달린 링크를 누르면 이 탭이 그 항목의 날짜로 열리고 해당 줄이 잠시 강조됩니다. 자세한 규칙은 위의 [`@일정`](#일정--말로-하는-일정-관리) 절을 보세요.
* **공문 분석 결과로 등록하는 절차**:
  1. AI 탭에서 `/조치`로 공문을 분석합니다.
  2. 답변 아래 **`일정으로 등록 (n건)`** 버튼을 누르면 후보 목록이 펼쳐집니다. 각 후보에는 기한, `D-day`, `원문 확인` 또는 `원문에서 찾지 못함`, `연도 추정`, `AI가 빠뜨려 코드가 찾음` 배지와 근거 문장이 함께 표시됩니다.
  3. **원문에서 근거를 확인한 항목만 기본으로 체크**되어 있습니다. 미확인 항목도 목록에서 지우지 않으므로, 원문을 보고 직접 체크해 등록할 수 있습니다.
  4. `n건 등록`을 누르면 일정 탭에 추가됩니다. 같은 공문을 다시 분석해도 이미 등록한 항목은 `완료` 표시와 함께 잠겨 중복으로 쌓이지 않습니다.
* **보기 방식 (월 · 주 · 일 · 목록)**: 상단 전환 막대로 고르며, 마지막에 본 방식이 다음에 열 때도 유지됩니다.
  * **월**: 어느 달이든 6주 42칸 격자로 그려 달을 넘겨도 격자 높이가 흔들리지 않습니다. 칸에는 일정 두 건까지 보이고 나머지는 `+n`으로 접힙니다. 지난 기한은 붉은 칩과 점, 완료한 일정은 취소선으로 표시합니다. **날짜를 누르면 그 날 일정이 격자 아래에 펼쳐지고**, `이 날 추가`를 누르면 그 날짜가 채워진 채로 추가 폼이 열립니다.
  * **주**: 일요일부터 이레를 하루씩 쌓아 보여 줍니다. **일**: 하루만 봅니다. `‹ ›`로 이동하고, 가운데 날짜 이름을 누르면 오늘로 돌아옵니다.
  * **목록**: 기한 지남 · 오늘 · 이번 주 · 나중 · 기한 미정으로 나뉘며, 완료 항목은 접혀 있습니다.
* **기한 미정 항목**: 달력 칸에 넣지 않습니다(없는 기한이 생깁니다). 대신 달력 아래에 `기한 미정 n건 보기` 띠로 남으며, 누르면 목록 보기로 넘어갑니다.
* **탭 배지**: 탭 이름 옆에 이번 주까지의 임박 건수가 표시됩니다.
* **항목 관리**: 동그라미를 눌러 완료 표시, 항목을 눌러 근거 문장·제출물·문의처·출처 공문 확인, 연필 아이콘으로 수정, 휴지통 아이콘으로 삭제(확인 후)합니다. 출처 공문 이름을 누르면 해당 공문을 새 탭에서 엽니다.
* **직접 추가**: 공문과 무관한 업무도 `직접 추가`로 기한과 메모를 넣어 함께 관리할 수 있습니다.
* **기한 알림**: 설정 → `기한 알림`에서 켜고 끌 수 있으며 알릴 시각을 고를 수 있습니다(기본 오전 9시). 지난 기한·오늘·내일 기한을 하루 한 번 묶어 알립니다.
* **내보내기**: 목록 아래 `CSV`(근거 문장 포함, 완료 항목까지)와 `ICS`(기한이 있는 남은 일정만, `TZID=Asia/Seoul`)를 지원합니다. CSV는 표 계산기의 수식 주입을 막는 처리를 거칩니다.

### 도구(Tool) 탭 및 공문 본문·첨부 자동화

![온나라 sAIde 도구 탭 및 공문 본문·첨부 다운로드 화면](docs/screenshots/06-automation.png)
*(사용 설명용 예시 · 온나라 sAIde 실제 UI / 샘플 데이터)*

사이드패널 상단의 **도구** 탭을 클릭하면 AI 모델 추론 없이 온나라 본연의 작업을 고속으로 처리할 수 있는 자동화 공간이 열립니다.

* **공문 본문 및 첨부파일 일괄 순차 다운로드**:
  * **다운로드 대상 선택**: **첨부파일만**, **본문만(HTML/PDF)**, **본문 + 첨부파일 전체** 중 원하는 모드를 선택할 수 있습니다.
  * 체크한 여러 공문의 본문과 첨부파일을 누락 없이 순차적으로 다운로드합니다.
  * 브라우저가 각 파일 다운로드를 완전히 마친 것을 감지한 후 다음 파일로 안전하게 넘어갑니다.
* **자동화 대기열 및 영구 실행 기록**:
  * 다운로드 작업과 **AI 분석 작업(`/요약`·`/조치`)이 같은 대기열**에 섭니다. 온나라 작업 탭을 두 작업이 동시에 만지지 않고, 진행 상황과 취소 버튼이 이 탭에 함께 보입니다.
  * 30초를 넘긴 작업이 끝나면 알림으로 알려 줍니다(설정에서 끌 수 있음). 맡겨 두고 다른 일을 하다 돌아올 수 있습니다.
  * 사이드패널을 닫았다가 다시 열어도 이전 다운로드 이력이 유지됩니다.
  * 완료된 파일 항목에서 **`파일 열기`**를 누르면 운영체제 기본 프로그램으로 열리고, **`폴더 열기`**를 누르면 Windows 탐색기에서 다운로드 폴더가 열립니다.

### 공문 PDF 뷰어 본문 자동 추출

온나라에서 공문 본문이 HTML 글자가 아니라 **웹 브라우저 내장 PDF 뷰어**로 열리는 경우, 일반적인 DOM 파싱 방식으로는 글자를 가져올 수 없습니다.

* 온나라 sAIde는 화면과 동일한 세션 쿠키/로그인 상태를 유지한 채 PDF 원본 스트림을 수신합니다.
* 확장의 **숨겨진 오프스크린(Offscreen) 문서** 내에서 `PDF.js` 라이브러리를 통해 텍스트 레이어를 고속으로 추출합니다.
* 폰트가 내장되지 않은 한국 행정 표준 PDF 문서를 완벽히 판독할 수 있도록 **한국어 CMap(Character Map)** 패키지가 확장에 기본 동봉되어 있습니다.
* 스캔 이미지로만 구성되어 OCR이 불가능한 PDF는 임의로 내용을 왜곡하거나 지어내지 않고, 읽지 못한 사유를 사용자에게 정직하게 안내합니다.

### 환경설정 및 AI 모델 연결

![온나라 sAIde 환경설정 및 AI 모델 연결 화면](docs/screenshots/03-settings.png)
*(사용 설명용 예시 · 온나라 sAIde 실제 UI / 샘플 데이터)*

확장 프로그램 아이콘을 우클릭하고 **옵션(Options)**을 선택하거나 사이드패널 설정 아이콘을 누르면 상세 설정 화면이 열립니다.

* **연결**: Ollama 엔드포인트(기본값 `http://localhost:11434`), 대화 모델(기본값 `gemma4:e2b`), 임베딩 모델(기본값 `bge-m3`)을 지정하고 `연결 확인`으로 설치된 모델 목록과 상주 상태(CPU/GPU)를 점검합니다.
* **성능**: 생각하기 모드(`끔` / `에이전트만` / `항상`), 페이지 본문 토큰 예산(기본 2,000), 문맥 창 `num_ctx`(기본 4,096), 모델 상주 시간 `keep_alive`(기본 10분), 패널 열 때 워밍업, `temperature`를 조정합니다. 값을 바꾸면 예상 첫 응답 시간이 함께 계산되어 표시됩니다.
* **에이전트**: 툴 호출 사용 여부와 루프 턴 상한(기본 8턴)을 정합니다. 브라우저 조작은 상한과 무관하게 매번 승인 카드를 거칩니다.
* **정확도 기록**: 답변과 기한 후보에 누른 `맞음`·`틀림`이 쌓여 누적 정확도와 대상별 표로 보입니다. 분석 결과 캐시의 저장 건수도 여기서 보고 비울 수 있으며, `사용법 다시 보기`로 첫 실행 안내를 다시 띄울 수 있습니다. **모든 기록은 이 컴퓨터 안에만 남습니다.**
* **첨부 파일 저장**: 내려받는 첨부의 이름을 `보고일자_공문제목_원래이름`으로 정규화할지, 브라우저가 정한 이름 그대로 둘지 고릅니다. 공문마다 하위 폴더를 만드는 선택지도 있습니다.
* **알림**: 기한 알림과 함께, **30초를 넘긴 작업이 끝났을 때 알릴지**를 정합니다.
* **공유/공람 브리핑**: 자동 브리핑 켜기·확인 주기·확인 시작/종료 시각·주말 제외, 지정된 대상 화면 확인·해제, 대상 범위(전체/키워드)와 포함·제외 키워드, 열람 처리 방식, 기록 보관 기간을 정합니다. 자세한 설명은 위의 [공유/공람 탭](#공유공람-탭-자동-브리핑) 절에 있습니다.
* **데이터 백업 및 복원 (Backup & Restore)**: 대화 세션, 일정/할 일, 공유/공람 원장/실행 기록, 기억(임베딩 제외/포함 선택 가능), 프리셋, 설정 데이터를 단일 JSON 파일로 내보내거나(Export), 무결성 검증을 거쳐 이전 상태로 안전하게 복원(Import)할 수 있습니다(`unlimitedStorage` 지원).
* **성능 기록 · 프리셋 편집기 · 기억 관리 · 페이지 접근 권한 · 표시(테마/언어)** 항목이 같은 화면에 이어집니다.

> ℹ️ **공급자 선택과 기능별 모델 지정은 아직 화면에 없습니다.** 공급자 계약(`lib/llm/provider.ts`), 설정 해석기(`lib/llm/config.ts`), 외부 전송 판정(`lib/llm/transfer-policy.ts`)과 `.env`·`storage.managed` 규격은 정의되어 있으나, 현재 실행 경로는 로컬 Ollama 한 갈래입니다. 범정부 AI 공통기반 어댑터와 선택 UI는 계획서 §6.8의 후속 작업입니다.

### 로컬 기억 및 지식 저장소 (Memory)

![온나라 sAIde 로컬 기억 및 지식 저장소 화면](docs/screenshots/04-memory.png)
*(사용 설명용 예시 · 온나라 sAIde 실제 UI / 샘플 데이터)*

* **기본은 꺼짐(옵트인)**: 기억은 설정에서 켜야 쌓입니다. 켜지 않으면 `/기억`은 "기억이 꺼져 있다"고 알리고 아무것도 저장하지 않습니다.
* **로컬 벡터 데이터베이스 (Dexie / IndexedDB)**:
  * 켠 뒤에 읽은 페이지 본문이 조각으로 나뉘어 로컬 브라우저 저장소에 보관됩니다.
  * **하이브리드 검색**: 로컬 임베딩 모델(`bge-m3`)의 벡터 검색과 키워드 검색(BM25)을 각각 순위로 낸 뒤 RRF로 섞습니다. 뜻이 가까운 글은 벡터가, `2026-1234호`·법령명처럼 정확히 그 글자를 찾는 질의는 키워드가 잡습니다.
  * 한국어 조사에 걸리지 않도록 낱말과 **한글 2-gram**을 함께 색인합니다(`예산을`·`예산 편성`이 서로를 찾습니다).
  * Ollama가 꺼져 있어 임베딩을 만들지 못해도 키워드만으로 찾아 줍니다.
  * 제외할 도메인과 보관 기간(기본 30일)을 지정할 수 있습니다.
* **데이터 관리 및 보관 주기**:
  * 저장된 공문 기억 목록을 조회하고, 불필요한 문서는 개별 삭제하거나 전체 초기화할 수 있습니다.
  * 외부로 데이터를 반출하지 않고 내 PC 내부에서만 유지됩니다.

## 자주 묻는 질문 (FAQ) 및 문제 해결

### Q1. 온나라 문서를 클릭했는데 "팝업이 차단되었습니다"라는 안내가 나옵니다.
* **원인**: Microsoft Edge의 기본 보안 정책에 의해 백그라운드 상세 팝업 창 생성이 차단된 경우입니다.
* **해결 방법**: Edge 브라우저 주소창 우측의 팝업 차단 아이콘을 클릭하고, 온나라 시스템 주소에 대해 **`항상 팝업 및 리디렉션 허용`**으로 설정해 주세요.

### Q2. "해당 프레임에 접근 권한이 없습니다" 배너가 뜹니다.
* **원인**: 공문 본문 뷰어나 첨부파일 다운로드 서버가 온나라 메인 포털과 다른 도메인(출처)에 위치해 브라우저 권한이 없는 경우입니다.
* **해결 방법**: 오류 배너에 함께 제공되는 **`권한 허용`** 버튼을 클릭하여 해당 도메인에 대한 접근 권한을 한 번만 승인해 주시면 즉시 읽기가 가능합니다.

### Q3. Ollama 모델 연결에 실패하거나 응답이 없습니다.
* **원인**: Ollama 데몬이 실행 중이지 않거나 CORS 환경 변수가 누락된 경우입니다.
* **해결 방법**:
  1. 터미널에서 `ollama serve` 또는 작업 표시줄 트레이에서 Ollama가 켜져 있는지 확인합니다.
  2. 시스템 환경 변수에 `OLLAMA_ORIGINS=chrome-extension://*`가 등록되어 있는지 확인하고, 등록 후 Ollama를 재시작합니다.
  3. `http://localhost:11434` 주소로 웹 브라우저에서 접속했을 때 `Ollama is running` 문구가 나오는지 확인합니다.

### Q4. 기한 알림이 오지 않습니다.
* **확인 1**: 설정 → **`기한 알림`**이 켜져 있고 `알릴 시각`이 지났는지 확인하세요. 알림은 그 시각 이후 브라우저를 처음 쓸 때 **하루 한 번** 뜹니다.
* **확인 2**: 지난 기한·오늘·내일 기한이 하나도 없으면 알리지 않습니다(이번 주 기한은 탭 배지로만 보여 줍니다).
* **확인 3**: Windows 설정 → `시스템` → `알림`에서 Microsoft Edge의 알림이 꺼져 있지 않은지 확인하세요. 브라우저가 완전히 종료된 동안에는 알리지 못합니다.

### Q5. 등록한 일정이 사라졌습니다.
* **원인**: 일정은 이 브라우저 프로필의 로컬 저장소(IndexedDB)에만 있습니다. 브라우저 데이터 삭제 시 함께 지워집니다.
* **해결 방법**: 중요한 기한은 일정 탭 아래 **`CSV`** 또는 **`ICS`**로 내보내 보관하세요. 대화를 지워도 일정은 남지만, 브라우저 저장소를 비우면 복구할 수 없습니다.

### Q6. 이전 문서 요약 내용이 새 문서를 요청할 때 섞여서 나옵니다.
* **해결 방법**: 사이드패널 상단의 **본문 칩 우측 `×` 버튼**을 누르거나, 새로운 문서를 다룰 때는 슬래시 명령(`/요약`, `/조치` 등)으로 시작하세요. 슬래시 명령을 실행하면 이전 대화는 보존되면서 모델에 전달되는 문맥(`contextFrom`)이 자동으로 초기화됩니다.

### Q7. 자동 브리핑이 뜨지 않습니다.
* **확인 1**: 설정 → `공유/공람 브리핑` → **`자동 브리핑`이 켜져 있는지** 확인하세요. **기본값은 꺼짐**입니다.
* **확인 2**: **대상 화면이 지정돼 있어야 합니다.** 온나라에서 `공유/공람 > 받은문서` 목록을 연 뒤 공유/공람 탭에서 `이 화면을 브리핑 대상으로 지정`을 한 번 눌러 주세요.
* **확인 3**: 브리핑은 **브라우저가 실행 중이고 온나라에 로그인돼 있을 때만** 동작합니다(사이드패널은 닫혀 있어도 됩니다). 세션이 끊겨 건너뛴 실행은 사유와 함께 기록에 남습니다.
* **확인 4**: 온나라 작업 탭을 다른 작업(문서 읽기·첨부 받기)이 쓰고 있으면 브리핑은 줄을 서지 않고 **다음 알람으로 미룹니다.** `지금 확인`으로 직접 실행할 수 있습니다.
* **확인 5**: 주기 확인을 켰다면 **지금이 업무시간 창 안인지, 주말이 아닌지** 확인하세요. 창 밖과 주말에는 확인하지 않습니다(하루 한 번 모드에는 적용되지 않습니다). 또한 새 문서가 없으면 알림은 뜨지 않습니다 — 확인은 했는지 공유/공람 탭의 실행 기록에서 볼 수 있습니다.

### Q8. 브리핑을 하면 문서가 열람 처리되나요?
* **아니요(기본값 기준).** 기본 설정 `목록만 읽기 (미열람 유지)`에서는 목록 표만 읽고 본문을 열지 않으므로 문서는 `미열람` 그대로 남습니다. 브리핑 전후로 열람 상태가 바뀐 문서가 있으면 그 건수를 공유/공람 탭 머리말에 알립니다.
* 설정에서 `브리핑한 문서를 열어 열람 처리`를 고른 경우에만 문서를 엽니다. **열람 처리는 온나라 서버가 기록하므로 확장이 되돌릴 수 없습니다.**
